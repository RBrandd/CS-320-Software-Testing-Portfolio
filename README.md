# CS-320-Software-Testing-Portfolio
# CS 320 Software Testing, Automation, and Quality Assurance

## How can I ensure that my code, program, or software is functional and secure?

I can make sure my code is functional by testing it against the requirements and not just testing whether the code runs without errors. In this course, I used JUnit tests to check things like valid and invalid inputs, required fields, length limits, unique IDs, and different operations within the services. Testing both the expected situations and situations that should fail helped me find problems that I might not have noticed just by looking at the code.

I also learned that testing needs to continue when changes are made to the software. Automated tests make this easier because I can run the same tests again without having to manually check everything. Security is also important because the software should not accept information that violates its requirements or allow unexpected input to cause problems. Using requirements to guide my tests gives me a better way to make sure the program is doing what it is supposed to do.

## How do I interpret user needs and incorporate them into a program?

I interpret user needs by breaking them down into specific requirements that the program needs to meet. In Project One, the requirements for the contact service explained things such as what information a contact needed, how long an ID could be, and what operations the service needed to support. Instead of making assumptions about what the program should do, I used those requirements to determine how the classes and methods should work.

The testing portion also showed me why understanding the requirements is important. If I misunderstand a requirement, I can write code that works but still does not meet what the user actually needs. Writing tests based on the requirements gives me another way to make sure the finished program matches what was requested.

## How do I approach designing software?

I approach software design by first understanding the requirements before writing the code. I try to break a larger problem into smaller parts so that each class and method has a specific purpose. Working on the Contact, Task, and Appointment services helped me understand the importance of keeping the different parts of a program organized and making sure each part is responsible for what it is supposed to do.

I also think testing should be considered during the design process instead of being something added at the very end. When I know what needs to be tested, it makes me think more carefully about how the code should handle valid inputs, invalid inputs, and unexpected situations. Overall, this course taught me that good software is not just about getting the code to work. It is about understanding the requirements, designing the program around them, and testing the results to make sure the software actually meets those requirements.
